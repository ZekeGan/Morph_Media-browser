## 遊戲內容頁

此畫面位於「資料夾內容」區，可承接 CARD／TREE／TABLE 選取的遊戲資料夾。線稿只表達上下分區，不指定固定框線、比例或最終樣式。

遊戲組件只用於人工 ROOT、自動辨識或遊戲候選資料夾（`shared/media.ts` 的 `isGameFolder`），候選需明示未確認；一般集合／一般目錄使用一般資料夾內容，不只依專案分類判定。CARD／TABLE 的「全部資料夾／邊界的資料夾」篩選與此呈現資格一致，TREE 不加此切換。顯示候選不等於保存 ROOT、不自動綁定／執行遊戲，也不放寬候選暫停與內部保護；明確 not-game 仍優先。

## 遊戲 ROOT 邊界

遊戲 ROOT 指單一遊戲的內容根，與專案選取的根不同；遊戲專案根可能只是包含很多遊戲的收藏目錄。

```text
Games/                  ← 專案根，仍須找出各遊戲
├─ Game-A/              ← 已辨識遊戲 ROOT，到此停止深入
│  ├─ Game.exe
│  └─ Data/             ← 不納入一般遞迴掃描，不在此建立記錄
└─ Game-B/              ← 另一遊戲 ROOT
```

已確認：

- 專案分類為遊戲時，發現遊戲 ROOT 就停在該資料夾，不繼續掃其內部。
- 其他分類掃到疑似遊戲資料夾時，要提示使用者是否繼續往內掃。
- 目的是保護遊戲內容的純淨，避免將程式內部目錄當成一般媒體資料夾處理。

### 與既有設計的關係

- 邊界必須在進入子資料夾及寫入子記錄前判定；不能先遞迴寫入，再回頭提示。
- 專案分類仍是檢視／掃描設定，不因分類為遊戲就認定專案根本身是遊戲，也不自動將分類寫入資料夾值。
- 停止深入後，TREE 可將其視為葉節點並標示「遊戲根／內部未掃描」。未掃描不等於真的沒有子資料夾。
- 遊戲邊界優先於繼續深入。C-80 已確認維持精確深度：例如專案根為第 1 層、遊戲 ROOT 在第 2 層，設定只顯示第 4 層時，不把它冒充第 4 層列出，也不深入遊戲；掃描結果提示停止路徑及原因，可引導調整顯示深度。
- C-80 已接受 ROOT 本身保留一份 `.media-viewer` 可攜資料目錄（沿用記錄、圖片與備份策略），不在其內部子目錄建立記錄；不能將「一份」誤作只能有一個實體檔案。遊戲原有檔案及內部目錄不移動、不改寫、不刪除。
- 先前掃描已在遊戲內部建立的記錄，不隨新邊界自動刪除；若要清除，需走既有歸屬檢查與清理預覽，原始遊戲檔案不變。

## 辨識與提示流程

### 方案比較

| 方案 | 優點 | 代價 |
| --- | --- | --- |
| **特徵提出候選＋人工修正（推薦）** | 新增遊戲後可協助發現邊界，使用者能修正誤判；適合持續增加收藏。 | 需維護特徵規則、候選狀態與確認流程，不保證自動辨識完整。 |
| 純手動標記「到此停止掃描」 | 判斷可預期，第一版規則較簡單。 | 每個新遊戲都需處理，數量多時操作較多。 |

C-80 採特徵候選＋人工修正與集中處理；純手動仍作無法辨識時的入口。流程如下，儲存細節仍待設計：

1. **唯讀淺層辨識**：以目前資料夾名稱清單及規則指定的有限子路徑提出候選，不執行 EXE、不為辨識先深入整個程式資料樹。各引擎覆蓋及限制見 [引擎辨識規畫](GAME_ENGINE_DETECTION.md)。
2. **保留依據**：單一 `.exe`、資料夾名稱或 `Data` 不能直接證明是遊戲。引擎／來源特徵可以增加可信度，但仍需可修正；工具、模組、啟動器及遊戲集合目錄都可能誤判。
3. **邊界分流**：使用者已確認的 ROOT，遊戲專案直接停；疑似或其他分類候選先暫停該分支深入，顯示原因與選項。其他不相關分支可繼續掃描。
4. **提示批次化**：仍要提示，但建議將多個候選集中處理，提供「停在這裡」「繼續掃描」及「這不是遊戲」；避免每筆都打斷操作。記住選擇的範圍及是否一次性仍待定。
5. **純淨含義清楚**：依使用者最新「不影響遊戲內的資料夾」，候選處的「繼續」採唯讀查看內部，不等於授權在遊戲內部寫記錄；畫面需標示唯讀、不可攜編輯不適用。明確修正為「這不是遊戲」才恢復一般掃描規則。遊戲內部可寫納管另議，不能以深度設定或提示確認暗中開啟。
6. **設定分離**：使用者確認的內容身分／辨識依據，與本專案是否深入的選擇分開；遍歷偏好不當成共用欄位值，也不因位於某分類而自動改內容類型。確切儲存契約待設計。

辨識依據範例：Unity 官方列出 Windows 建置中的執行檔、`UnityPlayer.dll` 及 `<ProjectName>_Data` 目錄，可作「程式內容根」候選線索；這不是所有遊戲的通用判定，也不能單憑引擎確定作品分類。[Unity Windows 建置檔案](https://docs.unity3d.com/6000.0/Documentation/Manual/WindowsStandaloneBinaries.html)

## 大圖與工具列

- 匯入的自訂圖片沿用可攜原圖策略；選既有資料夾圖片時沿用其穩定資產引用，避免重複複製。不自動輪播或搜尋網站封面；使用者指定圖片網址的匯入依下節。

### 圖片網址匯入

- 遊戲封面更換入口新增「圖片網址」來源；使用者提供圖片直連後，由程式下載並匯入，不需先手動存檔。不依網址抓取整個網頁、猜測封面或自動批次搜尋。
- 沿用現有主題與封面選擇流程，提供載入、圖片預覽及清楚的錯誤狀態。確認匯入後保存為該資料夾的可攜圖片資產，再更新封面引用；不能僅保存遠端 URL 當封面，離線或跨設備仍可讀取。
- 下載由 main 受控執行，接受合法 HTTP(S) 圖片網址，沿用既有遠端圖片的來源、重新導向、逾時、大小及內容驗證限制；依實際圖片內容辨識，不只信任副檔名／MIME。拒絕非圖片與未授權路徑，不為匯入啟動遊戲或初始化遊戲內部記錄。
- 取消、下載／解碼失敗、保存衝突或保存失敗時，原封面與引用保留；回收本次未成功納管的暫存資料。驗收常見圖片格式、錯誤連結、非圖片、超限、重新導向、快速換網址、取消及重開／離線顯示，不寫入原始遊戲媒體。
- 大圖預設保留完整比例；封面組件另可選填滿裁切或模糊填滿（見 [CELL 目錄](CELL_CATALOG.md)）。
- C-80 採推薦按鈕設定：樣式與排列共用專案版型；每個遊戲資料夾各自綁定實際 EXE 與存檔資料夾目標，避免改版型就讓所有遊戲指向同一個程式。
- 任務先用明確型別「啟動 EXE」「開啟資料夾」，預留擴充接點；不實作成任意系統指令字串。
- 編輯欄位包含按鈕文字、圖示／樣式、任務類型與目標選擇；可帶參數，工作目錄固定為 EXE 所在處；不支援自訂工作目錄或專用啟動器。
- 按鈕可顯示目標提示；缺少或搬移失效時呈現未綁定／重新指定入口。掃描、讀取或恢復記錄本身不啟動程式。

## 路徑、參數與執行責任

- 遊戲內 EXE 優先保存相對於該遊戲 ROOT 的位置，隨遊戲搬移解析目前路徑；由使用者指定目標，不自動選第一個 EXE。
- 存檔可能在 ROOT 外。可讓使用者選外部資料夾，但換設備時需重新指定，不承諾舊絕對路徑仍可用；不支援以系統已知目錄做可攜定位。
- 開啟外部存檔資料夾只表示開啟目標，不連帶將它加入掃描、寫入記錄或清理範圍。
- renderer 傳任務 ID 與資料夾身分，由 main 解析並驗證目前目標、型別及存在狀態。EXE 與參數分開處理，避免 shell 字串組合；工作目錄與遊戲啟動後的生命週期需驗證。
- 參數設計基線：保存有順序的 `args[]`，保留每個參數內的空白／引號；不用空白直接拆字串，也不把 EXE、參數串接成 shell 命令。參數 UI 與可攜路徑標記待細化，不假設參數中的任意舊設備路徑可自動修復。此為實作建議，不代表額外開放腳本或通用命令。
- 開啟資料夾可沿用 Electron 桌面開啟能力；需要工作目錄／參數的 EXE 可評估 Node 的直接程序啟動 API，不因文件提供能力就當成目前 POC 已支援。
- 設計基線：按鈕版型隨專案設定保存；各遊戲的實際目標與參數隨該資料夾可攜記錄保存，外部絕對路徑失效則重綁。穩定動作 ID、跨專案同名按鈕映射及覆寫的確切 schema 尚待設計，不以顯示文字自動配對。資料夾共用值及顯式私有覆寫的既定原則維持不變。

官方參考：[Electron shell](https://www.electronjs.org/docs/latest/api/shell)、[Node child_process](https://nodejs.org/api/child_process.html#child_processspawncommand-args-options)。實作時核對當時 Electron 內含 Node 版本；本輪未執行任何遊戲或程式。

### Mac 遊戲執行條件（未支援）

不支援（[C-130](DECISIONS.md#c-130不支援-mac-原生遊戲啟動2026-11-05)）：`bindTarget`／`runTarget` 只支援 EXE／資料夾，以下是 Mac 啟動的條件，不是現有能力。辨識與 bundle 保護見 [Mac 與多平台規則](GAME_ENGINE_DETECTION.md#mac-封裝與多平台規則)。

- 新增明確的 macOS App 目標／平台資訊，與 Windows EXE 分開保存及驗證，不以「開啟資料夾」繞過 EXE 限制。綁定實際 `.app`，保存相對於合法外層遊戲 ROOT 的位置；App 內不寫可攜記錄，也不改既有 EXE 綁定的語意。
- 啟動前核對主機平台、App／plist／對應主執行檔、路徑範圍與連結；macOS 另核對最低系統版本、CPU 架構／可用相容層及可執行權限。相容性未知顯示未驗證，不把檔案存在視為保證能跑；Windows 不從檔案權限推定 macOS 實機結果，也不嘗試原生執行 `.app`。
- Windows 可辨識並保護 Mac 遊戲，啟動入口須顯示需 macOS／目前平台不相容；同款存在 Windows 版時讓使用者明確綁定該目標，不自動猜第一個 EXE。不因本次需求加入模擬器、Wine、Android 安裝／啟動或任意腳本命令。
- 只在使用者明確點按後透過 macOS 系統 App 啟動機制執行，參數保持有順序的陣列並與目標分離；不硬套 Windows 的 EXE 工作目錄規則。原生機制、參數及工作目錄行為須以受控 App 驗證，不能直接拼 shell 字串。
- 系統信任、簽章、隔離、權限或缺檔造成拒絕時，顯示失敗並保留綁定供重新指定，不自動移除隔離、改權限、重簽章、修補 bundle 或改安全設定。掃描／預覽不啟動 App；未知引擎的有效 App 仍可由使用者明確綁定。
- 驗收包含 Windows 平台拒絕、macOS 原生啟動／參數、App 改名／搬移／失效、架構／最低版本／權限不符與系統拒絕；只能在受控資料驗證。macOS 實機未執行時明列限制，不宣稱已支援原生啟動。

## 操作編輯與目標

版型以可拖放清單及屬性區編輯，提供鍵盤排序；保存／取消保持草稿語意。從內容「自訂操作與目標」直接開遊戲操作 TAB。目標選擇器以當前資料夾作初始位置，選取並保存後才綁定；參數屬對應動作並用字串陣列保存。指定應用程式開檔分別選 EXE 與檔案，任一步取消都不寫入；執行用 argv、不經 shell。網址限定無憑證的 http(s)，路徑／連結／目標型別於保存與執行時驗證。

### 自動提供的操作（R-305～R-310）

不必綁定，main 依遊戲資料夾與記錄推算後放在內容頁按鈕列的已綁定動作後面；只顯示推算得出的項目，按下才執行。「用 Steam 啟動」「在 … 開啟」「開啟存檔資料夾」**預設不顯示**（R-315）：設定「遊戲操作」分頁的「其他按鈕」列出推算得出的項目，按眼睛才放進按鈕列（存在記錄的 `details.shownExtras`）。路徑只由 main 推算或使用者在系統對話框選擇，畫面只知道名稱與狀態。

- **用 Steam 啟動**（R-307）：ROOT 有 `steam_appid.txt`（只接受數字），或資料夾有 Steam 匯入的 App ID 時出現，開啟 `steam://run/<appid>`，讓疊加介面、成就與 DRM 正常。沒有程式處理 `steam://` 時按鈕停用並說明「這台電腦沒有安裝 Steam」。
- **在 … 開啟**（R-310、R-316）：資料夾有 Steam、DLsite、FANZA、BOOTH 匯入的商店網址時出現（Steam 優先），按鈕寫出站名；VNDB、Bangumi 等資料庫頁不算商店，不出現按鈕。只開 `https`，用系統瀏覽器。
- **開啟存檔資料夾**（R-305）：Unity 讀 `*_Data/app.info` 的公司與產品名 → `AppData\LocalLow\公司\產品`；Ren’Py 讀 `game/options.rpy` 的 `config.save_directory` → `AppData\Roaming\RenPy\…`；RPG Maker MV/MZ 用 `www/save`／`save`；RPG Maker XP～Ace 與 WOLF 用 `Save`。名稱只接受單一資料夾名（不含路徑符號），推算出的資料夾必須存在。推算不出來時，在設定「遊戲操作」分頁「存檔資料夾」自己指定（存在記錄的 `details.saveFolder`），也能改回自動。只開啟資料夾，不讀寫存檔。
- **遊玩時間**（R-308）：只記從 M:orph 直接啟動的 EXE 程序，程序結束才算一次（不到一秒不算）；M:orph 先關閉、經 Locale Emulator 或 Steam 啟動的那次不計。累計秒數、次數與最後遊玩時間存在本機設定 `playtime`（依資料夾身分），不寫進可攜記錄、不進設定包。內容頁按鈕列後面顯示；卡片的「系統資訊」組件可選「遊玩時間」「最後遊玩」；有遊戲的專案在表格多兩欄，可排序。

### 附帶程式與說明書（R-306）

設定「遊戲操作」分頁列出 ROOT 第一層的設定程式（`config.exe`、`setup.exe`、`環境設定*.exe`、`*config*.exe`）與說明書（PDF、HTML，或 `readme*`／`manual*`／`説明書*` 等文字檔），排除 `unins*`、`vcredist*`、`dxsetup*` 等安裝與執行環境程式。按「加入」才綁定：沒用過的同類按鈕（「設定程式」「說明書」）沿用，否則新增一個按鈕到專案工具列；說明書用新的動作類型「開啟資料夾內的檔案」（`file`，只限遊戲資料夾內的 PDF、HTML、TXT、MD、RTF，用系統預設程式開啟；程式、腳本與可夾帶程式碼的 CHM 不能用這個類型，以免變成執行）。已綁定的檔案不再列出。不自動加入、不執行。

### Locale Emulator（R-309）

應用程式設定「一般」可指定 `LEProc.exe`（只在 main 的檔案對話框選，檔名必須是 `LEProc.exe`），存本機設定 `localeEmulator`。已綁定的 EXE 動作可選「用 Locale Emulator 啟動」：「日文（預設）」執行 `LEProc.exe -run <exe> <參數…>`；也可選在 Locale Emulator 裡建立的設定檔（例如簡體中文，讀自 LEProc.exe 旁的 `LEConfig.xml`，只取名稱與 GUID），執行 `LEProc.exe -runas <GUID> <exe> <參數…>`（R-319）。選擇記錄在該目標的 `localeEmulator`（`true` 或 GUID）；Locale Emulator 裡已刪掉的設定檔顯示「找不到的設定檔」。未指定 LEProc.exe 時選單停用並提示。原本用 `.lnk` 捷徑的做法照常可用。

### Flash 遊戲（R-320）

應用程式設定「一般」可指定播放 `.swf` 的程式（Flash Player projector 或 Ruffle 桌面版，只在 main 的檔案對話框選，必須是 `.exe`），存本機設定 `flashPlayer`。「啟動遊戲」這類 EXE 動作選檔時也接受 `.swf`；執行時以 `<播放程式> <swf> <參數…>` 開啟，計入遊玩時間。M:orph 不附帶、不內嵌任何 Flash 執行環境。未指定播放程式時，啟動會提示到應用程式設定指定。
